# 📄 Arquitetura do App Flutter – Task Pair App

## 1. Arquitetura Geral

O app deve seguir **Clean Architecture + Feature First + Firebase Services**.

## 1.1 Camadas da Arquitetura

```text
Presentation (UI)
    |
State Management
    |
Domain (Entities + UseCases)
    |
Data (Repositories)
    |
Data Sources (Firebase)
```

### Descrição das Camadas

| Camada       | Responsabilidade               |
| ------------ | ------------------------------ |
| Presentation | Telas, Widgets                 |
| State        | Gerenciamento de estado        |
| Domain       | Regras de negócio              |
| Data         | Implementação dos repositórios |
| Data Sources | Firebase Auth / Firestore      |

# 11. Regras Importantes do Sistema

## Regras principais

1. Toda tarefa pertence a um par
2. Toda tarefa tem recorrência
3. Recorrência gera ocorrências
4. Ocorrência gera execução
5. Execução gera validação
6. Validação gera pontuação
7. Pontuação gera progresso
8. Progresso gera recompensa
